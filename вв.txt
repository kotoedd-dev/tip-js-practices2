# КР2 — Технологии индустриального программирования

Вагелист Дмитрий Эдуардович · ЭФБО-15-25 · РТУ МИРЭА · 15.11.2026.

Требования: Node.js 20+ (проверено на Node.js 24.21.0), npm, Chrome/Edge. Приложения не требуют npm install. Python нужен только для дополнительной страницы демонстрации ПР5, не для API.

Три проекта скопированы из starter преподавателя. Исходный репозиторий преподавателя использован без изменений; его commit и контрольные суммы файлов указаны в report/source-integrity.txt. Индивидуальный вариант не задан; КР выполнена на общем наборе. Серверы, исходные серверные данные и проверки сохранены.

## Запуск

Из этой папки в терминале PowerShell:

```powershell
cd practice-04
npm.cmd start
```

Открыть http://127.0.0.1:5504/; браузерные проверки: http://127.0.0.1:5504/checks.html.

Во втором терминале:

```powershell
cd practice-05
npm.cmd start
```

API: http://127.0.0.1:5505/api. В третьем терминале из practice-05: `npm.cmd run client`.

Перед ПР6 остановить ПР5 сочетанием Ctrl+C. Затем:

```powershell
cd practice-06
npm.cmd start
```

API: http://127.0.0.1:5505/api; интерфейс: http://127.0.0.1:5506/; проверки: http://127.0.0.1:5506/checks.html. Ctrl+C останавливает оба сервера. ПР4 может работать одновременно с ПР6.

## Проверка пяти заданий

1. В ПР4 открыть http://127.0.0.1:5504/examples/kr2-evidence.html. Страница действительно вызывает validateTaskDraft для двух названий. Листинг — report/listing-1.js.txt.
2. В ПР4 выбрать общий набор и «Все», нажать штатный сброс. Ввести id=20, название «Изучить localStorage», приоритет «Высокий», добавить. Обновить тот же адрес. F12 → Application → Local storage → http://127.0.0.1:5504 → tip-js-practice-04:demo. Проверить version=1 и задачу 20 в tasks.
3. В ПР5 при запущенном API выполнить npm.cmd run client: основной запрос getTasks({completed:false,priority:'high'}) возвращает ids=[4,13,34], meta.total=3.
4. Та же команда выполняет await getTaskById(999) внутри try/catch: kind=http, status=404. Чтобы открыть отдельные страницы демонстрации, из practice-05 запустить `python -m http.server 5510 --bind 127.0.0.1`, затем открыть http://127.0.0.1:5510/evidence.html и http://127.0.0.1:5510/evidence.html?error. Они выполняют реальные запросы, а не выводят заранее заданные ответы.
5. Остановить ПР5, запустить ПР6. Нажать «Восстановить учебные данные» и подтвердить. Установить только статус «В работе» и нажать «Применить». Открыть F12 → Network, очистить журнал. Завершить задачу «Подготовить модель задач» (id=4). Должны появиться PATCH /api/tasks/4 → 200 и следующий GET /api/tasks?completed=false → 200, задача исчезает. OPTIONS preflight перед PATCH нормален.

## Фактические проверки

В каждом practice-XX запустить npm.cmd test. ПР4: 35 + 27 = 62/62; ПР5: 18 + 26 + 13 = 57/57; ПР6: 23 + 33 + 14 = 70/70. Всего 189 проверок Node.js, ошибок 0.

Браузерные: ПР4 — 23/23. ПР6 — 12/14 в неизменённом комплекте преподавателя. Дефект теста создания: waitFor вызывает requireNode, который бросает исключение сразу, если асинхронно создаваемой карточки ещё нет. Следующий reset может пересечься с незавершённым POST, из-за чего следующий тест видит 13 задач вместо 12. Тесты не правились. Независимая проверка с ожиданием появления карточки и завершения reset подтвердила оба сценария: создание id=35 и отказ невалидной формы без POST. Подробности: report/browser-06.txt и report/extra-e2e.txt. Браузерного комплекта ПР5 нет; его проверки выполнены в Node.js.

Все пять сценариев КР2 реально проверены. JSON результатов и журнал сети находятся в report/.
